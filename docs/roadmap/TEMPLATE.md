## Problem and decision

Describe the concrete failure or duplication and the smallest useful change.
Distinguish proposed behavior from current support. State any unresolved design
or ownership question.

## Evidence and acceptance

Give a reduced example, exact source revision, relevant fixture or public link.
Separate fresh results from historical reports/source inspection and list missing
platform evidence. State observable acceptance criteria and failure behavior.

## Beam workaround and removal

Name the binding, parser, branch or caller workaround that would disappear.
State what must remain and link related cards for independently landable slices.
For a product card without a shim, state the useful caller outcome instead.

## Next action

Name the next reproduction, discussion or patch and its owner when assigned.
For an upstream API, record the first complete providing version when known,
then use the [migration rule](README.md#migration-and-ownership). A card does not
itself authorize an upstream write or a supported-toolchain change.
